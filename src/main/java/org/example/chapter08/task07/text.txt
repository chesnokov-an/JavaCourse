Потоки данных в Java позволяют описывать вычисления в декларативном стиле.
Поток не хранит элементы, а передаёт их через цепочку промежуточных операций.
Источником потока может быть коллекция, массив, файл или генератор.
Метод filter отбирает элементы, метод map преобразует каждый элемент,
а метод flatMap заменяет один элемент потоком и объединяет результаты.
Операции limit, skip, distinct и sorted относятся к промежуточным операциям.
Оконечная операция запускает вычисления и получает результат.
Методы count, max, min, findFirst и collect являются оконечными операциями.
Потоки могут быть последовательными и параллельными.
Параллельный поток разбивает работу на части и объединяет результаты.
При этом не следует изменять коллекцию, которая является источником потока.
Потоковая обработка удобна для фильтрации, преобразования и группировки данных.
Коллекторы позволяют собрать результат в список, множество, строку или отображение.
Метод groupingBy группирует элементы по ключу, а partitioningBy делит их на две группы.
Метод reduce сводит все элементы потока к одному значению.
Класс Optional помогает безопасно работать с отсутствующим результатом.
Потоки примитивных типов IntStream, LongStream и DoubleStream экономят упаковку.
Метод codePoints удобен для обработки символов Unicode.
Потоковые операции выполняются лениво и только при необходимости.
Например, limit может остановить обработку раньше, чем будет прочитан весь источник.
Потоки данных не заменяют коллекции, а дополняют их.
Коллекция хранит элементы, а поток описывает вычисление над ними.
Поток можно создать из массива с помощью метода Arrays.stream или Stream.of.
Для примитивного массива метод Stream.of создаёт поток из одного массива.
Метод IntStream.of создаёт поток целых чисел и позволяет использовать сумму и среднее.
Промежуточные операции возвращают новый поток и не изменяют исходный.
Оконечная операция потребляет поток, поэтому повторно использовать его нельзя.
Ленивость позволяет работать с очень большими и даже бесконечными источниками.
Метод findFirst может завершить обработку, как только найден подходящий элемент.
Метод anyMatch проверяет, есть ли хотя бы один элемент с нужным свойством.
Метод allMatch проверяет, что все элементы удовлетворяют условию.
Метод noneMatch проверяет, что ни один элемент не удовлетворяет условию.
Методы sum, average, max и min доступны для потоков примитивных типов.
Для группировки результатов часто используется класс Collectors.
Коллектор counting подсчитывает количество элементов в каждой группе.
Коллектор joining объединяет строки в одну строку с разделителем.
Коллектор mapping применяет функцию к элементам перед накоплением.
Потоковая обработка хорошо сочетается с лямбда-выражениями и ссылками на методы.
Ссылка на метод делает код короче и выразительнее.
Например, String::length можно передать в метод mapToInt.
Потоки следует применять там, где важна декларативность, а не ручной цикл.
Иногда обычный цикл оказывается проще и быстрее, особенно для небольших коллекций.
Параллельный поток не всегда быстрее последовательного.
Накладные расходы на разбиение и объединение результатов могут быть значительными.
Поэтому перед распараллеливанием стоит измерить время выполнения.
Корректность параллельной обработки требует независимости операций.
Нельзя изменять общий источник данных во время выполнения потока.
Потоковые вычисления не должны зависеть от порядка, если поток параллельный.
Исключением являются операции, которые явно требуют порядка.
Метод forEach не гарантирует порядок в параллельном потоке.
Метод forEachOrdered сохраняет порядок элементов.
Метод unordered сообщает, что порядок не важен для дальнейших операций.
Это может ускорить выполнение некоторых промежуточных операций.
Потоки можно объединять с помощью методов concat и flatMap.
Метод concat создаёт поток из двух потоков подряд.
Метод flatMap используется, когда каждый элемент порождает несколько элементов.
Поток строк можно разбить на слова с помощью метода split.
Метод codePoints возвращает поток кодов символов строки.
С его помощью можно проверить, что строка состоит только из букв.
Проверка идентификатора Java требует отдельной проверки первого символа.
Первый символ должен быть допустимым началом идентификатора.
Остальные символы должны быть допустимыми частями идентификатора.
Такая проверка работает с Unicode и не сводится к английским буквам.
Поток токенов можно получить из файла с помощью метода lines.
Метод Files.lines читает файл построчно и возвращает поток строк.
Этот поток нужно закрывать, поэтому его используют в try-with-resources.
Из потока слов можно получить первые сто элементов с помощью limit.
Для подсчёта частоты слов используется группировка и коллектор counting.
Результат группировки можно отсортировать по значению и вывести первые десять слов.
Потоки удобны для обработки текстов, логов, отчётов и других наборов данных.
Они позволяют отделить источник данных от операций над ними.
Библиотека сама выбирает порядок выполнения и может оптимизировать вычисления.
При этом важно не злоупотреблять потоками и сохранять читаемость кода.
